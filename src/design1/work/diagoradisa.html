§ 01 — Context

The problem was not the model.

Stomatologists photograph lesions in the mouth and classify them by eye. The classification is slow, inconsistent between clinicians, and hard to audit.

Diagoradisa was built to make that process measurable: a tool to annotate images against a controlled disease taxonomy, a pipeline that turns those annotations into a training set, a model that segments lesions, and an app that returns a case-level result.

The taxonomy started at 95 ICD-10 classes. The production model uses 18. That reduction is the most important design decision in the project. A class with 30 examples teaches a model to be confidently wrong. The 18 surviving classes are the ones with enough evidence to support a claim.

§ 02 — Constraints

What made it hard.

  • One developer, four services. No handoff to an ML engineer, a designer, or an ops team. The seams were mine to keep.
  • Clinical data. Real patient photographs, authentication on every surface, and no identifiers in the exported dataset.
  • One GPU. A training run is an appointment, not a loop. Experiments had to be chosen carefully.
  • Variable capture. Different cameras, lighting, and EXIF orientations. The data is not a benchmark set.
  • The model must be allowed to say nothing. A confident wrong answer is worse than no answer. That requirement shaped the aggregation rules and the UI.

§ 03 — Architecture

Three services in the request path. One in the basement.

The annotator owns the data. The ML service owns the weights. Palmist owns the clinician's session and nothing else — it has no domain database, only a user table and a proxy. Meta owns the machine they run on.

§ 04 — Surfaces

Four tools, one workflow.

Annotator

The dataset comes from here

Clinicians work through assigned batches, draw polygons or boxes, and label each finding against the ICD-10 taxonomy. The ML-readiness screen shows the export cascade before anyone trains: how many images survive the minimum-sample filter, and which classes are about to disappear.

  • Deep zoom on full-resolution photographs.
  • Polygon, rectangle, and SAM 2 click-to-segment.
  • Batches, roles, and per-entity policies.
  • A dashboard that makes class imbalance visible before training.

ML service

Training, evaluation, serving

The stoma package runs the lifecycle: check the dataset, train, evaluate, compare predictions to ground truth, assess a run, export weights, and serve. Every model is a run with an ID, so a metric can always be traced back to the weights that produced it.

  • Experiment and run model with lineage.
  • Compare reports with IoU matching and error images.
  • 29 API endpoints, model hot-swap without a restart.
  • Greek and English labels resolved at the wire boundary.
$ stoma data check --experiment yolo-min150-640px-bg-20260614
  clean · 18 classes · 8,774 images
$ stoma train
$ stoma assess --latest
  box mAP@50 0.508 · recall 0.496

Fig. 05One CLI for the whole run lifecycle.

Palmist

The clinician's surface

Upload up to ten images as one case. The app forwards them to the ML service, aggregates detections across views, and only calls a condition present when it appears in two or more views. Results export to PDF and Excel.

  • Case-level aggregation instead of per-image noise.
  • Camera capture and quality checks on mobile.
  • Explicit empty and no-detection states.
  • A design system with seven primitives and a living pattern page.

Meta

The part nobody demos

Containerised deploys from an operator workstation, an Apache reverse proxy, database backups, security headers, and migrations that are opt-in. The annotator has run in production since August 2025.

  • Multi-stage images and a pinned compose project.
  • Reverse proxy with rate limiting and hardened headers.
  • Opt-in migrations, so a deploy cannot surprise the schema.
$ ./scripts/deploy.sh prod --migrate
$ docker compose -f docker-compose.prod.yml up -d
✔ app tier healthy · migrations applied · proxy reloaded

§ 05 — Failures

Three things that went wrong.

These are the parts I would put in a hiring conversation. Each one changed how I work.

01

7.1% of the dataset had rotated labels.

Symptom
Masks landed beside the lesion on portrait photographs. The model was learning from noise.
Cause
The annotator exported label coordinates against the raw image size. The browser draws annotations in the EXIF-applied frame. On iPhone portrait shots, the two frames are 90° apart.
Fix
Export against the transposed size, rebuild the dataset, re-run the baseline. Box mAP@50 went from 0.460 to 0.508; recall from 0.423 to 0.496.

754 of 10,575 images were affected. The compare report found it; the aggregate metric had not.

02

Recall stopped at 0.49.

Symptom
The model missed half the lesions. mAP looked respectable; recall did not.
Attempts
Class reweighting, a 1024 px retrain, label-space collapse, calibration, a frozen DINOv2 probe, and an RF-DETR A/B.
Result
All closed. RF-DETR produced 51 background false positives against YOLO's 12 on clean ground truth. The failure is the data, not the architecture.

The next lever is acquisition: more annotated images, especially for the weak classes.

03

The safety layer did nothing.

Symptom
Four post-processing gates were meant to suppress bad predictions before they reached a clinician.
Test
ON/OFF A/B on 210 cases. The gates touched about 0.6% of detections.
Result
No net benefit. I removed the engine, the environment flag, four response fields, and the calibration loader.

Shipping it was the mistake. Testing it was the fix.

Ten cases is a product test, not a validation study. It shows the failure modes — a confident wrong class, a refusal to choose, a missed lesion — not the error rate. The honest summary: four correct, three wrong, three abstentions.

§ 07 — Next

What I would do with another quarter.

  1. Acquire data, not architecture. The recall ceiling is a data problem. More annotated images for the weak classes, and a class-set drift guard so the taxonomy cannot grow silently.
  2. Make annotation cheaper. SAM 2 already segments from a click. Feeding model proposals back into the annotator would close the loop between prediction and dataset growth.
  3. Turn the ten-case test into a habit. A dated, repeatable product test per model version — the same ten folders, the same UI, the same table — so regressions are visible before a clinician finds them.
